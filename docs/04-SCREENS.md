# 화면 설계

> 전제: **슬랙이 주 소비 채널, 웹은 관리·분석 화면.**
> 따라서 웹은 "예쁜 탐색"보다 **밀도 높은 정보와 빠른 조작**을 우선한다.

---

## 공통

- 다크/라이트 모두 지원 (`prefers-color-scheme` + 토글)
- 상단 네비: `대시보드 / 알림함 / 설정`, 우측에 워커 상태 점(초록=정상, 주황=일부 소스 실패, 빨강=중단)
- 가격은 항상 `₩238,000` 형태, 변동은 `▼ 12,000 (-4.8%)` 색상 대비
- 모든 시각은 KST 표시 + `2시간 전` 상대 시간 병기

```
┌───────────────────────────────────────────────────────────────┐

```

**카드에 반드시 담아야 하는 것 (이게 이 화면의 전부다)**

1. 현재 최저가 (크게)
2. 직전 대비 변동률 (색상)
3. 30일 스파크라인 — "지금이 싼 건가?"에 즉답
4. 목표가 대비 위치 (달성/부족액)
5. 최저가에 해당하는 실제 날짜·항공사
6. 즉시 조회 버튼 (기다리기 싫을 때)
7. **신선도 점** — 최저가 옆에 초록 ●(실측) / 회색 ○(캐시)
8. **커버리지 미터** — `112/180칸 (62%)`. 작은 바로

**빈 상태 문구를 조심할 것.** "조건에 맞는 항공권이 없습니다"는 **사실이 아니다** —
항공권이 없는 게 아니라 우리가 못 본 것이다. 반드시 이렇게 쓴다:

> **"아직 데이터를 못 찾았습니다 (0/180칸)"**

Travelpayouts 캐시는 사용자 검색 이력 기반이라 인기 없는 날짜는 비어 있는 게 정상이고,
샘플링이 돌면서 점차 채워진다. 사용자가 "비싸서 없는 것"으로 오해하면 안 된다.

- 상태가 `paused`면 카드 회색 처리 + `일시중지` 뱃지
- 마지막 실행이 `failed`면 카드 상단에 주황 스트립 + 실패 소스명

## S2. 감시 등록 `/watches/new`

3스텝 위저드. **한 화면에 다 넣지 않는다** (항공/숙소 필드가 완전히 다름).

**Step 1 — 무엇을 감시할까**
- 큰 버튼 2개: `✈️ 항공권` / `🏨 숙소` (패키지는 Phase 2, 비활성 표시)

**Step 2 — 조건 (항공권 기준)**

| 필드 | 컨트롤 | 비고 |
|---|---|---|
| 출발지 / 도착지 | 자동완성 (`/api/meta/airports`) | "후쿠" 입력 → FUK 후쿠오카 |
| 여행 시기 | 날짜 범위 피커 | **단일 날짜가 아니라 범위**가 기본. 이게 이 서비스의 차별점 |
| 체류 기간 | 슬라이더 `2박 ~ 3박` | 왕복일 때만 |
| 출발 요일 선호 | 요일 칩 멀티선택 | 미선택 = 무관 |
| 인원 / 좌석 | 스텝퍼 / 셀렉트 | |
| 직항만 | 토글 | |

**Step 3 — 알림 규칙**
- `목표가` 입력 (필수 아님) → 입력하면 `threshold` 규칙 자동 추가
- 체크박스 3개:
  - ☑ 평소보다 `20`% 이상 떨어지면 알림 (`drop_pct`)
  - ☑ 역대 최저가를 찍으면 알림 (`all_time_low`)
  - ☐ 최저가가 갱신될 때마다 알림 (`new_best`) — 시끄러울 수 있음 경고 표시
- 확인 주기 셀렉트: `1시간 / 3시간 / 6시간(기본) / 12시간 / 하루`
- 하단에 **미리보기**: "이 조건이면 하루 약 4회 조회, 예상 알림 주 1~2건"

저장 → 즉시 1회 수집 실행 → 상세 화면으로 이동 (로딩 상태 표시)

## S3. 감시 상세 `/watches/[id]`

```
┌───────────────────────────────────────────────────────────────┐
│  ← 가을 후쿠오카            [수정] [일시중지] [지금 조회] [⋮] │
│  ICN → FUK · 2~3박 · 성인 2 · 이코노미 · 6시간마다            │
├───────────────────────────────────────────────────────────────┤
│   현재 최저   ₩238,000     90일 최저 ₩238,000  평균 ₩291,400  │
│                                                                │
│   [ 가격 히스토리 차트 — 30일 / 90일 / 전체 ]                 │
│   ─── 최저가   ┈┈ 중앙값   ▬▬ 목표가(250,000)                 │
│   알림 발생 지점에 🔔 마커                                     │
├───────────────────────────────────────────────────────────────┤
│  현재 오퍼 (12건)             정렬: [가격순 ▾]  소스: [전체 ▾]│
│  ┌────────────────────────────────────────────────────────┐   │
│  │ ₩238,000  11/14(금)~11/16(일)  JJA 진에어  직항        │   │
│  │  ● 12분 전 실측 · Bright Data 검증 ✓        [예약하기] │   │
│  ├────────────────────────────────────────────────────────┤   │
│  │ ₩244,000  11/21(금)~11/23(일)  TW 티웨이  직항         │   │
│  │  ○ 최대 7일 전 캐시 · ⚠ 참고가              [예약하기] │   │
│  └────────────────────────────────────────────────────────┘   │
├───────────────────────────────────────────────────────────────┤
│  커버리지  180칸 중 112칸 (62%)                                │
│  ┌── 달력 히트맵 ────────────────────────────────────────┐    │
│  │ 11월  ■■□■■■■ ░░□■■■■ ■□□░░■■ ■■■□□□■              │    │
│  │ 12월  □□░░■■■ ■■■□□□□ ░░░□□■■ ■■□□░░░              │    │
│  │ ■ 값 있음   □ 빈칸   ░ cold(3회 헛침)                 │    │
│  └────────────────────────────────────────────────────────┘   │
├───────────────────────────────────────────────────────────────┤
│  ▸ 실행 로그 (접힘)   ok 18 · partial 2 · failed 0            │
└───────────────────────────────────────────────────────────────┘
```

- 차트는 Recharts `ComposedChart`. 최저가 라인 + 중앙값 점선 + 목표가 참조선 + 알림 마커
- **커버리지 영역**을 최저가 라인 아래에 옅게 깐다. 커버리지가 낮았던 구간은
  라인을 회색 점선으로 — "이 구간의 상승은 데이터 부족일 수 있음"을 시각적으로 알린다
- **180칸 달력 히트맵** — 어디가 비었는지, 샘플링이 제대로 도는지 한눈에 보인다.
  구현 시 `dataviz` 스킬을 로드해 색·접근성(색맹 대비)을 맞춘다
- 오퍼 행에 **소스 뱃지**를 반드시 표시 (어디서 온 값인지 신뢰도 판단용)
- **신선도 점**을 반드시 표시한다 — 초록 ●(live, Bright Data 실측) / 회색 ○(cached, 최대 7일 전)
  Travelpayouts 캐시는 사용자 검색 이력 기반이라 최대 7일 묵는다. 숨기면 신뢰가 무너진다
- "검증 ✓"은 3단계 수집(SCAN→SAMPLE→VERIFY)의 VERIFY를 통과한 가격임을 뜻함
- 예산 소진으로 검증을 못 한 오퍼는 `⚠ 참고가`로 표시하고 툴팁에 이유를 적는다
- 실행 로그는 기본 접힘. 펼치면 실행별 상태·소스별 성공/실패·소요시간

## S4. 알림함 `/alerts`

- 시간 역순 리스트, 미읽음 굵게 + 좌측 색 바 (info 회색 / good 파랑 / great 주황)
- 각 행: 심각도 아이콘, 제목, 요약, Watch 이름(링크), 발송 채널 아이콘, 시각
- 필터: `전체 / 미읽음`, Watch별
- 행 클릭 → 해당 Watch 상세의 그 시점으로 이동 (차트에 해당 지점 하이라이트)

## S5. 설정 `/settings`

**알림 채널**
- 활성 채널 토글 (슬랙 / 인앱 / 텔레그램). 텔레그램은 토큰 없으면 비활성 + 안내
- 슬랙 Webhook URL 입력 + `[테스트 발송]` 버튼 → 결과 인라인 표시
- 쿨다운 시간, 방해금지 시간대(이 시간엔 great만)

**소스 상태** ← 디버깅에 가장 유용한 패널
```
소스              상태      마지막 성공     비고
travelpayouts     ● 정상    3분 전          —
brightdata        ● 정상    12분 전         크레딧 1,847/5,000 (37%)
hotellook         ● 정상    3분 전          —
tourapi           ○ 미설정  —               DATA_GO_KR_KEY 없음
crawler:*         ○ 비활성  —               CRAWL_ENABLED=false
```

**예산** ← 유료 소스가 생겼으므로 필수 패널

```
Bright Data 크레딧
████████░░░░░░░░░░  1,847 / 5,000

이번 달 말까지 하루 약 105회 여유
검증 1,203 · 샘플링 644 · 소진 예상 없음
```

- 소진 임박 시 경고, 소진 시 **"검증 없이 알림 발송 중"** 배너
- 매월 1일 갱신됨을 명시

**샘플링 정책** ← `app_settings.sampling_policy`를 직접 편집. 재배포 불필요

| 항목 | 기본값 | 설명 |
|---|---|---|
| `boundary_price_ratio` | 1.30 | 인접 가격이 목표가의 몇 배까지 경계 탐색할지 |
| `cold_after_probes` | 3 | 몇 번 헛치면 포기할지 |
| `cold_retry_days` | 7 | cold 셀 재시도 주기 |
| `per_run_sample_budget` | 5 | 실행당 샘플링 호출 수 |
| `sample_cap_ratio` | 0.70 | 월 예산 중 SAMPLE 상한 비율 |
| `coverage_drop_gate` | 0.5 | 커버리지가 이 배수 이하로 떨어지면 알림 보류 |

> **이 값들은 전부 추측이다.** `probe_log`의 적중률을 보고 실데이터로 고친다.

**수집**
- 기본 주기, 검증 임계 비율, 크롤링 활성화 토글(경고 문구 동반)
- 데이터 보관 기간, `[오래된 오퍼 정리]` 버튼
